# REST API для управления задачами

## 1. Описание проекта

REST API для управления списком задач, разработанный на Python с использованием Django REST Framework и PostgreSQL.

API позволяет создавать, просматривать, редактировать, удалять и фильтровать задачи.

**Базовый адрес:** `http://127.0.0.1:8000`

**Формат обмена данными:** JSON

## 2. Эндпоинты

| Метод | URL | Описание | Успешный код |
|---|---|---|---|
| GET | `/api/tasks/` | Получить список задач | 200 |
| POST | `/api/tasks/` | Создать задачу | 201 |
| GET | `/api/tasks/{id}/` | Получить задачу по ID | 200 |
| PUT | `/api/tasks/{id}/` | Полностью обновить задачу | 200 |
| PATCH | `/api/tasks/{id}/` | Частично обновить задачу | 200 |
| DELETE | `/api/tasks/{id}/` | Удалить задачу | 204 |

## 3. Структура задачи

| Поле | Тип | Описание |
|---|---|---|
| id | integer | Уникальный идентификатор, только чтение |
| title | string | Обязательное название, максимум 200 символов |
| description | string | Описание, необязательное |
| status | string | `todo`, `in_progress`, `done` |
| priority | string | `low`, `medium`, `high` |
| due_date | string/null | Срок выполнения в формате YYYY-MM-DD |
| created_at | datetime | Дата создания, только чтение |
| updated_at | datetime | Дата изменения, только чтение |

Значения по умолчанию: `status = "todo"`, `priority = "medium"`, `description = ""`, `due_date = null`.

## 4. Примеры запросов и ответов

### 4.1. Получение списка задач

**Запрос:** `GET /api/tasks/`

**Ответ — 200 OK:**

```json
[
  {
    "id": 1,
    "title": "Выполнить домашнее задание",
    "description": "Разработать REST API",
    "status": "todo",
    "priority": "high",
    "due_date": "2026-11-05",
    "created_at": "2026-10-30T09:00:00+06:00",
    "updated_at": "2026-10-30T09:00:00+06:00"
  }
]
```

Если задач нет, API возвращает `[]`.

### 4.2. Создание задачи

**Запрос:** `POST /api/tasks/`

```json
{
  "title": "Выполнить домашнее задание",
  "description": "Разработать REST API",
  "status": "todo",
  "priority": "high",
  "due_date": "2026-11-05"
}
```

**Ответ — 201 Created:**

```json
{
  "id": 1,
  "title": "Выполнить домашнее задание",
  "description": "Разработать REST API",
  "status": "todo",
  "priority": "high",
  "due_date": "2026-11-05",
  "created_at": "2026-10-30T09:00:00+06:00",
  "updated_at": "2026-10-30T09:00:00+06:00"
}
```

Идентификатор и временные метки формируются сервером. Приведённые значения являются примерами.

### 4.3. Получение одной задачи

**Запрос:** `GET /api/tasks/1/`

**Ответ — 200 OK:** JSON-объект задачи в формате, показанном выше.

Если задача не найдена, возвращается `404 Not Found`.

### 4.4. Полное обновление задачи

**Запрос:** `PUT /api/tasks/1/`

```json
{
  "title": "Обновлённое домашнее задание",
  "description": "Подготовить и проверить API",
  "status": "in_progress",
  "priority": "medium",
  "due_date": "2026-11-06"
}
```

**Ответ — 200 OK:** обновлённый JSON-объект задачи.

### 4.5. Частичное обновление

**Запрос:** `PATCH /api/tasks/1/`

```json
{
  "status": "done"
}
```

**Ответ — 200 OK:** полный JSON-объект задачи с обновлённым статусом.

### 4.6. Удаление задачи

**Запрос:** `DELETE /api/tasks/1/`

**Ответ — 204 No Content.** Тело ответа пустое.

## 5. Фильтрация задач

API поддерживает фильтрацию через параметры URL:

| Запрос | Результат |
|---|---|
| `GET /api/tasks/?status=todo` | Задачи, ожидающие выполнения |
| `GET /api/tasks/?status=in_progress` | Задачи в процессе |
| `GET /api/tasks/?status=done` | Выполненные задачи |
| `GET /api/tasks/?priority=high` | Задачи с высоким приоритетом |
| `GET /api/tasks/?status=todo&priority=high` | Задачи с двумя условиями |

## 6. Коды ответов и ошибок

| HTTP-код | Значение | Когда возникает |
|---|---|---|
| 200 OK | Успех | Получение или обновление задачи |
| 201 Created | Создано | Успешное создание задачи |
| 204 No Content | Удалено | Успешное удаление |
| 400 Bad Request | Ошибка данных | Неверный статус, приоритет, дата или пустое название |
| 404 Not Found | Не найдено | Задача с указанным ID отсутствует |
| 405 Method Not Allowed | Метод запрещён | HTTP-метод не поддерживается данным эндпоинтом |
| 500 Internal Server Error | Ошибка сервера | Непредвиденная внутренняя ошибка |

### Пример ошибки 400

Запрос:

```json
{
  "title": "   "
}
```

Ответ:

```json
{
  "title": [
    "Название задачи не может быть пустым."
  ]
}
```

### Пример ошибки 404

Запрос: `GET /api/tasks/99999/`

Ответ:

```json
{
  "detail": "No Task matches the given query."
}
```

Текст ошибки 404 может зависеть от настроек локализации Django REST Framework.

## 7. Запуск проекта

Для запуска необходимы Docker и Docker Compose.

В корневой папке проекта нужно подготовить `.env` на основе `.env.example` и настроить переменные окружения.

Затем выполнить:

```bash
docker compose up -d --build
docker compose exec back python manage.py migrate
```

API доступен по адресу:

`http://127.0.0.1:8000/api/tasks/`

## 8. Тестирование
